# 사용자 데이터 백업·복원 및 진단

설정 → **AI·기억·데이터 → 데이터 백업·복원**에서 사용합니다. 모든 작업은 로컬에서 실행하며 파일을 자동으로 전송하지 않습니다.

## 선택 백업

1. 타이머 기록, 앱·AI 설정, 사용자 이미지·이미지 세트, 저장된 AI 대화·기억·사용량 중 필요한 항목을 선택합니다. 대화·기억은 기본 선택되지 않습니다.
2. **백업 미리 보기**에서 파일 수와 대략적인 크기를 확인합니다.
3. **선택 항목 백업 저장**으로 `.seunga-backup.zip` 파일을 저장합니다. 저장할 때 JSON, SQLite, 이미지 내용을 검증합니다.

일반 데이터 위치는 `%APPDATA%\KyungheeAssistant`입니다. 별도 AI Review 실행의 `%LOCALAPPDATA%\KyungheeTimer_AI_Review\KyungheeAssistant`는 자동 검색·이동·병합하지 않습니다. 설치 폴더에서 사용하던 사용자 팩은 이미지 관리 기능이 사용자 데이터의 `imported_assets`에 보존한 이후 백업에 포함됩니다.

이미지 ZIP 팩은 **이미지 설정에서 가져오는 캐릭터 이미지 묶음**입니다. 사용자 데이터 백업은 **기록·설정·이미지·AI 데이터를 선택 복원하는 파일**이며 고유한 매니페스트가 있습니다. 서로의 가져오기 용도로 사용할 수 없습니다.

백업에는 다음 항목만 들어갑니다.

| 선택 항목 | 파일 |
| --- | --- |
| 타이머 기록 | `state.json` |
| 앱·AI 설정 | `settings.json`, `ai_settings.json`의 알려진 설정 필드 |
| 사용자 이미지·세트 | `images/`, `image_sets/`, `imported_assets/`의 지원 이미지, 이미지 세트 목록, `manual_asset_overrides.json` |
| AI 대화·기억·사용량 | `memory.sqlite3`, `ai_usage.sqlite3`의 알려진 테이블 |

`openai_key.dpapi`, 알 수 없는 파일·설정 필드, 원본 로그, 임시 파일, SQLite WAL/SHM 파일, 설치 폴더의 자동 채택 표시 파일은 내보내지 않습니다. 인식 가능한 API 토큰, Bearer 인증 값, 비밀번호 할당 문자열, PEM 개인 키는 텍스트에서 가립니다. 자유롭게 작성한 내용이나 이미지 속의 모든 비밀을 자동으로 알아낼 수는 없으므로, 선택한 대화·이미지는 개인정보가 포함된 일반 백업으로 취급해야 합니다. ZIP은 암호화되지 않습니다.

앱이 보관한 이미지 경로는 백업에서 상대 참조로 바뀌고 복원 위치에 맞게 다시 연결됩니다. 외부 원본 이미지의 절대 경로는 복사하지 않습니다. 설정만 복원하면 참조하는 이미지는 대상 PC에 이미 있어야 합니다. 이미지와 설정을 함께 선택하면 같은 선택 상태를 옮길 수 있습니다.

## 복원

1. **복원 파일 선택**에서 백업을 선택합니다. 파일 경로, 크기, 해시, JSON 구조, SQLite 무결성, 이미지 해독을 검사한 뒤 미리 보기를 보여 줍니다.
2. **선택 항목 복원 후 앱 종료**를 누르고 복원할 항목을 선택합니다. 마지막 확인 전에는 현재 데이터를 바꾸지 않습니다.
3. AI·날씨 등 진행 중인 작업이 있으면 종료될 때까지 기다린 뒤 다시 시도합니다.
4. 현재 데이터의 선택 항목을 `backups/before-restore-….seunga-backup.zip`에 먼저 저장합니다. 이를 만들 수 없거나 현재 데이터가 검증되지 않으면 복원을 중단합니다.
5. 백업을 다시 검증하고 같은 파일인지 확인합니다. 준비된 파일·폴더를 원자적 이름 변경으로 교체합니다. 오류가 발생하면 교체한 항목을 모두 원래 상태로 되돌립니다.
6. 성공하면 오래된 메모리 상태를 저장하지 않고 앱을 종료합니다. 앱을 다시 실행해 복원 결과를 확인합니다. API 키 파일과 이 PC의 키 보관 정책은 백업에서 가져오지 않습니다. 기존 보호 키 파일이 있으면 보호 보관 상태를 유지하여 다음 실행 때 삭제되지 않게 합니다. 실행 중에만 보관하던 키는 앱 종료와 함께 사라지므로 다시 입력해야 합니다.

복원은 선택한 항목을 백업 시점으로 되돌리는 작업입니다. 이후 추가한 같은 항목의 데이터는 먼저 만든 복구 백업에 보존됩니다. 빈 항목의 복원은 현재 그 항목을 비웁니다. 선택하지 않은 항목은 바뀌지 않습니다. Windows 시작 프로그램 등록 같은 운영체제 설정 자체를 ZIP이 실행하거나 바꾸지는 않습니다.

드물게 디스크 오류 등으로 자동 되돌리기까지 실패하면 앱이 종료됩니다. 이때 사용자 데이터의 `.restore-journal-*` 폴더에 원래 파일이 남으며 복구 백업도 보존됩니다. 강제 종료·전원 차단으로 중단된 트랜잭션도 같은 복구 자료를 남깁니다. 여러 파일을 하나의 파일시스템 연산으로 바꾸거나 전원 차단까지 자동 복구하는 것은 지원하지 않습니다. `committed` 표시가 없는 복구 폴더가 남아 있으면 앱은 설정·상태를 읽거나 저장하기 전에 시작을 거부하며 추가 복원도 차단합니다. 정상 완료 후 삭제하지 못한 `committed` 폴더는 시작을 막지 않습니다.

미완료 복구 안내가 나타나면 다음 순서로 처리합니다.

1. 앱을 다시 실행하거나 `.restore-journal-*`를 삭제하지 않습니다. 자동 되돌리기가 완료되었다고 가정하지 마세요.
2. 전체 사용자 데이터 폴더를 다른 안전한 위치에 복사합니다. 특히 `.restore-journal-*/originals`, `.restore-journal-*/transaction.json`, `backups/before-restore-….seunga-backup.zip`를 보존합니다. 복구 백업에는 선택했던 개인정보가 들어 있을 수 있습니다.
3. 지원 요청에는 우선 앱 버전, 표시된 오류 안내, 이미 만들어 둔 개인정보 제외 진단 JSON만 전달합니다. 복구 폴더나 대화 백업 자체는 개인정보 포함 여부를 확인하고 명시적으로 필요한 경우에만 별도로 공유합니다.
4. 보존한 복사본을 기준으로 원본 복구 또는 검증된 백업 복원을 확인한 뒤에만 미완료 폴더를 정리하고 앱을 시작합니다. 이 단계는 자동 처리하지 않으며, 어느 파일이 적용되었는지 확인하지 않은 채 폴더를 지워 시작 제한만 해제해서는 안 됩니다.

## 개인 정보 제외 진단 내보내기

진단 JSON에는 앱 버전, 운영체제 종류, Python 버전, 숫자·불리언으로 제한한 안전한 설정, 알려진 오류 분류만 포함합니다. 오류 분류는 최대 최근 로그 256 KiB에서 고정된 분류명만 추출합니다. 원본 로그 문장·예외 내용은 넣지 않습니다.

API 키, 대화·기억 내용, 타이머 기록, 이미지, 원본 로그, 절대 경로·사용자 이름, 날씨 지역, 커스텀 대사는 제외합니다. 파일을 어디에 공유할지는 사용자가 별도로 결정합니다.

## 안전 한도와 검증

- 최대 3,000개 파일, 파일당 64 MiB, 전체 512 MiB, JSON당 2 MiB입니다.
- 이미지 해상도는 2,400만 픽셀 이하이며 PNG/JPEG/WebP를 완전히 읽을 수 있어야 합니다.
- 경로 이탈, 절대 경로, Windows 장치 이름·ADS, 링크·정션, 중복 이름, 암호화 항목, 과도한 압축률을 차단합니다.
- 실행 중 SQLite는 파일 복사가 아닌 SQLite backup API로 일관된 스냅샷을 만듭니다. 알려진 테이블을 새 데이터베이스로 재구성하여 삭제된 페이지나 알 수 없는 테이블을 내보내지 않습니다.
- 복원은 프로필 쓰기가 중단되고 모든 SQLite 연결이 닫힌 경우에만 허용합니다. 앱에서 제공한 종료 콜백이 없으면 패널의 복원 버튼은 비활성화됩니다.
- 내보내기로 현재 사용자 데이터 파일을 덮어쓰지 못하도록 사용자 데이터 폴더 안에서는 `backups/`만 저장 대상으로 허용합니다.

개발 검증: `python -m unittest discover -s tests -p test_user_data_backup.py -v`. 테스트는 임시 프로필만 사용하며 실제 사용자 데이터나 네트워크에 접근하지 않습니다.
